# Decision log

- **ADR-027 — Same-origin minimal product shell:** accepted. The backend serves a dependency-free UI that uses only authenticated public APIs. The shell is public but contains no tenant data. JWT issuance and initial tenant bootstrap stay external; subsequent role administration is tenant-scoped and RLS-protected. Disabled features surface errors rather than fake results.

- **ADR-026 — Bounded process deployment:** accepted. A one-shot migration job gates API/worker startup; readiness checks database reachability, migration state, and draining. API shutdown stops admission and waits to a deadline; workers stop between bounded scheduler phases and rely on canonical lease recovery if forcibly terminated. Per-process pools and container resources are explicit. PostgreSQL remains lifecycle authority.

- **ADR-025 — Derived operational telemetry:** accepted. Workers persist only deployment identity, heartbeat, drain state, and bounded non-secret metadata. Queue, lease, usage, cost, and failure metrics are derived from canonical PostgreSQL records under tenant RLS. Structured JSON logging uses one recursive redactor and generated request correlation IDs; no vendor event store becomes lifecycle authority.

- **ADR-001 — Modular monolith:** accepted. API and workers are processes from one codebase and database, avoiding distributed transactions and competing runtimes.
- **ADR-002 — PostgreSQL source of truth:** accepted. Queue, leases, checkpoints, and idempotency ledgers live together. A future queue may notify but never own lifecycle state.
- **ADR-003 — Row locks plus versions:** accepted. `FOR UPDATE SKIP LOCKED` claims work; versions reject stale API writers.
- **ADR-004 — Fail closed on unknown effects:** accepted. Lease expiry never permits replay of a non-reconcilable external effect.
- **ADR-005 — Tenant keys everywhere:** accepted. Mandatory predicates prepare for RLS but do not replace authentication.
- **ADR-006 — Integer cost accounting:** accepted. Micro-US-dollars avoid floating-point budget errors.
- **ADR-007 — No fake production adapter:** accepted. Deterministic providers live only under tests; missing production configuration is an error.
- **ADR-008 — Database deployment neutrality:** accepted. `DATABASE_URL` is the only application database location contract. Compose, host, remote, and managed PostgreSQL use identical application and migration behavior.
- **ADR-009 — Provider registry and factories:** accepted. Provider IDs are open-ended strings; provider-specific mapping, validation, capabilities, and errors stay inside registered adapters. Retry and fallback are deferred to Stage 5.
- **ADR-010 — Engines are not providers:** accepted. The native engine coordinates a bounded model turn; providers perform inference transport. Neither owns durable state or terminal transitions.
- **ADR-011 — Hybrid components are bounded:** accepted. Future component adapters may replace planning, retrieval, context, memory, summarization, parsing, or bounded turns, but never lifecycle, leases, approvals, tools, idempotency, cancellation, budgets, audit, tenancy, or completion.
- **ADR-012 — No framework fallback:** accepted. An unavailable or invalid configured engine fails explicitly. Engine changes require a new run or persisted configuration revision.
- **ADR-013 — Kubernetes is optional infrastructure:** accepted. Multi-agent concurrency is implemented through leased workers and persisted child runs. Kubernetes may later scale worker pools or bounded jobs; it is never lifecycle authority and does not map one deployment to one logical agent.
- **ADR-014 — Approval freezes execution identity:** accepted. A sensitive proposal persists validated arguments, their canonical hash, tool and idempotency identity before releasing the lease. HTTP decisions never execute work. A later leased worker consumes the exact action once through `ToolExecutor`; rejection becomes a persisted deterministic tool failure for replanning.
- **ADR-015 — Retry requires semantic evidence:** accepted. Pure and externally idempotent tools may retry only configured error codes; uncertain effects become first-class unknown records. Reconciliation is a leased status lookup, never an implicit replay. Provider retries and fallbacks are bounded, explicit, capability-checked, and represented as separate attempts.
- **ADR-016 — Signed identity plus database membership:** accepted. The API validates configured HS256 JWTs and intersects signed roles with active tenant membership. It does not implement passwords or token issuance. JTI revocation is persisted; development headers are prohibited in production mode.
- **ADR-017 — RLS on the restricted API path:** accepted. Authenticated requests use a transaction-scoped tenant setting under a non-login least-privileged role. Explicit repository predicates remain mandatory. Workers retain owner authority for cross-tenant leasing, so worker database credentials require stronger isolation.
- **ADR-018 — Deterministic context with explicit approximation:** accepted. Required constraints fail closed when oversized; older trace rows remain authoritative, summaries and selection provenance are durable, and the current token estimate is disclosed rather than represented as provider-exact.
- **ADR-019 — Plans are evidence-bound runtime state:** accepted. Models propose acyclic revisions, while the canonical runtime derives readiness/attempts, preserves completed tasks, requires prior persisted evidence for terminal task states, and prevents completion with unfinished required work.
- **ADR-020 — Memory writes are deliberate governed effects:** accepted. Memory is separate from transcript/context state, carries ownership and provenance, and is never populated from every model message. Model proposals use an approval-only canonical tool under explicit per-agent scope/quota policy; exact resumption and idempotency remain owned by `ToolExecutor`. Retrieval is tenant/user/agent scoped, retention-aware, budgeted, provenance-recorded, and treated as untrusted data.
- **ADR-021 — RAG is a bounded native component, not a runtime:** accepted. Versioned documents and pgvector chunks remain tenant-owned PostgreSQL records. Embeddings must come from an explicitly configured real provider; absence or dimension mismatch fails closed. Context retrieval and `knowledge_search` share one permission-aware service, return content-hash citations, and label documents as untrusted evidence. Retrieval cannot change lifecycle, execute tools, or become an instruction channel. Exact vector search is preferred initially over premature indexing; scale-specific indexes require measured dimensions and corpus evidence.
- **ADR-022 — External capabilities enter through one approval-only tool:** accepted. MCP servers are tenant-owned connector configurations, not runtimes. Current stateless HTTP discovery persists bounded schemas and untrusted metadata. Models propose only `mcp_call`; the canonical approval service and `ToolExecutor` freeze, reauthorize, execute, account, and fail uncertain effects closed. Server annotations never select risk, retries, or approval. Exact origins, environment credential references, PostgreSQL rate limits, and revocation bound access; broader transports and DNS pinning remain explicit limitations.
- **ADR-023 — Multi-agent work is persisted child runs:** accepted. Supervisors propose the reconcilable `delegate_run` tool; children are ordinary canonical runs with parent/root identity, bounded roles/context/budgets, and PostgreSQL leases. Parents release leases into a durable wait and are requeued only after terminal children. Required failed/empty output blocks completion, cancellation propagates through descendants, and agent ancestry plus depth/fan-out limits prevent loops. Kubernetes may scale worker pools but never represents logical agents or owns lifecycle state.
- **ADR-024 — Evaluation observes canonical runs:** accepted. Suites are immutable dataset versions and every case queues an ordinary persisted run. A bounded scorer reads terminal trace evidence without owning lifecycle or changing run outcomes. Run-level agent snapshots make candidate identity durable. Deterministic providers remain test-only; model-dependent evaluations are recorded separately and never become uncontrolled paid CI calls.
