# Operational limitations

- The product surface is a minimal dependency-free UI, not a polished design system. It uses externally issued JWTs in session storage and does not implement signup, initial tenant bootstrap, login/password recovery, refresh, secure-cookie BFF, CSRF workflow, pagination controls, live updates, or browser automation. Connector and retrieval panels remain explicitly unavailable without their real backends.

- Compose resource limits and CI are reference controls, not proof on every cloud/runtime. The pressure test verifies exclusion over 12 queued runs, not sustained throughput. There is no automated PITR drill, autoscaler, Kubernetes manifest, PgBouncer deployment, or zero-downtime schema compatibility analyzer.

- Operational metrics are pull-based JSON rather than Prometheus/OpenTelemetry export. Worker health uses database heartbeats and a fixed 90-second threshold. Provider health verifies configured transport availability only. Automated telemetry retention and purge are not implemented.

- Authentication validates locally signed HS256 JWTs but does not issue tokens, manage passwords, integrate an external identity provider, or automate key rotation. Revocation is JTI-based and requires an operator-controlled write. Development headers are explicitly non-production.
- The native engine and Ollama `llama3.1:8b` are verified. Anthropic, Gemini, and OpenAI-compatible transports are implemented and contract-tested with validated synthetic wire responses, but no cloud/local-compatible credential-backed run was performed.
- Explicit bounded provider retry/fallback, deliberate durable memory, tenant-isolated document retrieval, governed skills, controlled stateless HTTP MCP connectors, persisted supervisor/child runs, durable deterministic evaluation scoring, and a minimal real-API product surface are implemented. There is no framework fallback, external execution engine, Kubernetes deployment, or hardened browser identity workflow.
- Evaluation uses exact rules rather than an LLM judge. Retrieval scoring is expected-document recall, citation scoring checks persisted source identity plus final-output URI, and run latency includes queue overhead. No dataset import/export, statistical confidence analysis, flaky-case quarantine, hosted dashboard, or automatic baseline promotion exists. Model-dependent evaluations are intentionally excluded from deterministic CI and were not manually run against paid providers.
- MCP support targets the current stateless HTTP protocol used by this stage and was verified against an in-process synthetic server, not a third-party deployment. It does not support legacy session-oriented transports, server-initiated sampling/elicitation, resources, prompts, task execution, OAuth discovery, or streaming progress. Discovered descriptions and annotations are untrusted and never set safety policy.
- Connector egress uses exact configured origins, scheme/userinfo/redirect checks, DNS private/special-address screening, bounded responses, explicit private-network opt-in, durable role checks, approval, and rate limits. The platform does not yet pin the preflight DNS answer into the underlying fetch connection, so DNS rebinding/TOCTOU hardening remains for deployment hardening; only trusted operator-controlled origins should be allowlisted. There is no general connector sandbox or proxy-enforced egress boundary.
- Connector bearer secrets are environment-referenced rather than persisted, but there is no secret-vault integration, automated credential rotation, mutual TLS, or OAuth flow. A compromised API/worker process can read its environment and make network calls with its authority.
- Memory relevance is deterministic lexical overlap and remains distinct from vector document search. Records and retrieved chunks are marked untrusted in context, metadata size is bounded, and provenance/citations are retained, but these controls cannot prove a statement is true or eliminate semantic poisoning and prompt injection.
- Retrieval accepts only caller-supplied text, Markdown, and JSON; it does not fetch URLs, parse PDFs/office files, perform OCR, scan malware, or validate factual content. Chunking and token estimates are deterministic approximations. Search is exact pgvector cosine ranking without an ANN index, so large-corpus performance is unverified. A process crash during embedding may leave a durable `pending` document requiring operator deletion/recovery; it never becomes current. Soft-deleted documents/chunks are filtered but physical purge is not automated.
- Context token counts use a deterministic character estimate rather than each provider's tokenizer. Summaries are deterministic extracts, not semantic model summaries. Plans remain local to one run; multi-agent work uses explicit child goals rather than distributing plan tasks automatically.
- Multi-agent verification uses deterministic test providers. Child runs can execute concurrently across multiple worker processes, but no load/soak test, priority scheduler, worker affinity, result streaming, distributed deadlock detector beyond bounded ancestry/depth, or real-model supervisor benchmark has been performed. Parent budget reservation is conservative: unused child budget is not released in Stage 11.
- Tool timeout cannot stop a handler that ignores its abort signal. Uncertain keyed effects become `unknown` and never replay automatically. Reconciliation works only for tools that implement a real lookup contract; otherwise operator resolution remains required. A `manual` reconciliation state keeps the run paused; this release does not provide an administrative API that records a final manual outcome.
- Cancellation is checked before and after provider calls, but providers may still bill a call that completes concurrently with cancellation.
- Approval authorization uses signed identities and effective roles intersected with active membership. RLS constrains the restricted API role; worker and migration owner credentials remain high-trust and must be isolated.
- A crash after an approved or ordinary tool invocation starts is classified as unknown and routed to configured reconciliation or manual handling. A model call interrupted by worker death fails closed because its provider outcome and possible cost cannot be proven.
- Failed provider attempts contribute usage/cost only when the provider adapter supplies usage with its normalized error. Providers that do not report failed-call usage can still charge amounts the platform cannot infer.
- Only Compose PostgreSQL 16 with pgvector was live-tested. Host, remote, and managed portability is presently a connection-string/code-path claim and additionally depends on a compatible `vector` extension; no second live database deployment was verified.
- Backup, PITR, HA, pooling guidance, full redaction policy, metrics, retention enforcement, and migration rollback procedures are not supplied.
- The initial release supports bootstrap from an empty PostgreSQL/pgvector database. It does not establish compatibility with private development databases created from the superseded pre-release migration chain; future public schema changes require reviewed forward migrations.
- No secure sandbox exists. Untrusted code and shell execution are unsupported.
